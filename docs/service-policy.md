# 서비스 정책 (Service Policy)

TrendFit의 정책을 회원 / 옷장 / 트렌드 수집 / 추천 / 구매 연동 5개 영역으로 나눈다.

> 🔸 표시는 **아직 결정되지 않은 항목**이다. 임의로 값을 정하지 말고 → **[open-decisions.md](open-decisions.md)** 를 따른다.

---

## 1. 회원 정책

| 항목 | 정책 |
|---|---|
| 인증 방식 | Google OAuth2 |
| 세션 관리 | JWT 액세스 토큰 + 리프레시 토큰 |
| 권한 | `enum Role { USER, ADMIN }` |
| 온보딩 필수 단계 | 스타일 취향 선택(최소 1개 이상, 다중 선택 가능) |
| 온보딩 선택 단계 | 체형 정보 입력 |

- **온보딩 스타일 태그 목록 (12개, ✅ 결정됨 2026-07-27):**
  미니멀 · 캐주얼 · 스트릿 · 러블리 · 페미닌 · 시크 · 빈티지 · 스포티 · 클래식 · 프레피 · 유니크 · 오피스룩
  - 캐주얼~포멀(캐주얼/오피스룩), 무드 스펙트럼(러블리~시크), 서브컬처(스트릿/유니크) 축을 고르게 배치.
  - `UserPreference.styleTags`에 콤마 구분 문자열로 저장하는 기존 설계([domain-design.md](domain-design.md) §3.1)는 유지하며, 값의 어휘집만 확정한 것이다.

## 2. 옷장 등록 정책

| 항목 | 정책 |
|---|---|
| 등록 방식 | 다중 이미지 일괄 업로드 |
| 1차 분석 | Claude Vision — 카테고리/색상/패턴/크롭 좌표 |
| 보정 방식 | 핏/재질 등 확신도 낮은 속성은 스와이프 UI로 사용자가 즉시 확정 |
| 이미지 처리 범위 | **크롭까지만** (완전 배경 제거/누끼는 MVP 범위 밖, 스트레치) |
| 최소 등록 벌 수 | ✅ 결정됨(2026-07-27): **3벌 이상 + 상의(TOP) 또는 원피스(DRESS) 1개 이상 & 하의(BOTTOM) 1개 이상** 보유 시 추천 활성화 |
| '+1 아이템' 자동 등록 | 구매 확정 콜백 수신 시, Vision 재호출 없이(이미 태그를 알고 있으므로) 즉시 등록 |

- 옷장은 온보딩 시 전량 등록을 요구하지 않는다. 소량(5~10벌)으로 시작해 지속 등록 및 구매 연동
  자동 등록으로 점진적으로 채워지는 것을 기본 정책으로 한다.
- 최소 등록 기준은 순수 개수가 아니라 **카테고리 조합**을 요구한다. 상의/하의(또는 원피스) 조합이
  없으면 재킷만 3개 있어도 코디를 조립할 수 없기 때문이다. Recommendation이 이 조건을 조회하는
  방식(예: `ClosetQueryPort`에 활성화 여부 조회 메서드 추가)은 구현 단계(4주차, B4)에서 확정한다.
- **이미지 저장소 (✅ 결정됨 2026-07-27, R2 구현 2026-07-29):** 로컬 개발 단계에서는 로컬
  파일시스템에 저장하되, `ImageStorage` 인터페이스로 추상화해 `LocalFileImageStorage` 구현체를
  둔다. Railway 배포는 `R2ImageStorage`(Cloudflare R2)로 전환한다 — 인터페이스 뒤에서
  교체되므로 ClosetService 등 호출 측 코드는 바뀌지 않는다. 전환은
  `trendfit.storage.provider=r2` 설정 하나로 이루어진다.

## 3. 트렌드 수집 정책

| 항목 | 정책 |
|---|---|
| 수집 주기 | 1일 1회 배치 (매일 새벽) |
| 수집 대상 | 로그인 불필요한 **공개** 패션 매체/RSS만 |
| 수집 제외 | 로그인 필요 SNS(인스타그램, 핀터레스트 등) — 이용약관 리스크로 MVP 제외 |
| 정제 방식 | Claude API로 컬러/아이템/무드 키워드 구조화 |
| 원문 처리 | 원문 재배포 금지, 요약·키워드 정제만 저장 |

- **최종 수집 소스 목록 (3개, ✅ 결정됨 2026-07-27):**
  - 보그 코리아 (`vogue.co.kr/feed`) — 하이패션, 시크/페미닌/클래식 무드
  - W코리아 (`wkorea.com/feed`) — 편집샷/룩북, 캐주얼~포멀 밸런스
  - 하입비스트 코리아 (`hypebeast.kr/feed`) — 스트릿/스니커/컬래보
  - 세 매체 모두 로그인 불필요, 유효 RSS 2.0 피드 확인됨(수집기 구현 전 실제 fetch로 재확인 필요).
    후보였던 무신사 매거진(RSS 503)·29CM(전용 RSS 없음)은 이번엔 보류.
    GQ코리아·마리끌레르는 RSS는 유효하나 헬스/연예/게임 콘텐츠 비중이 높아 트렌드 키워드 추출
    노이즈가 커서 제외.

## 4. 추천 정책

| 항목 | 정책 |
|---|---|
| 요청 유형 | (a) 일반 요청("오늘 뭐 입지?") (b) 앵커 아이템 요청("이거 입고 싶은데 뭐랑 매치?") |
| 입력 컨텍스트 | 오늘 날씨 + 최신 트렌드 키워드 + 사용자 취향 + 옷장 전체(ID+태그) |
| 날씨 API | ✅ 결정됨(A3, 2026-07-27): 기상청 단기예보조회(`getVilageFcst`, 공공데이터포털) — 최저/최고기온, 하늘상태, 강수확률을 3시간 간격으로 제공. 위경도→격자좌표(nx, ny) 변환 필요 |
| 처리 방식 | 프롬프트 조립(Context Injection) — 벡터DB 기반 RAG 사용 안 함 |
| 출력 | 의류 ID 기반 코디 조합 + 필요 시 '+1 아이템' 제안 (JSON) |
| 결과 표시 | 서버가 ID를 실제 이미지로 매핑, 클라이언트에는 사진으로 표시(텍스트 아님) |
| 요청 빈도 제한 | ✅ 결정됨(A5, 2026-07-27): **하루 10회/사용자** 소프트캡. 도그푸딩 규모(5~10명) 기준 넉넉한 상한이며, 초과 시 명확한 안내 메시지로 거절. 무료/프리미엄 티어 구분은 아직 없음(수익화 시점에 재검토) |

- 추천 엔진의 프롬프트 조립 대상은 [domain-design.md](domain-design.md) §2의 포트(`ClosetQueryPort`,
  `TrendQueryPort`, `UserPreferencePort`)를 통해서만 조회하며, 포트의 구체 위치·시그니처는
  §2에서 확정했다(B4).

## 5. 구매 연동 정책

| 항목 | 정책 |
|---|---|
| '+1 아이템' 표시 | 추천 결과에 네이버쇼핑 검색 API로 조회한 실제 상품(이미지/가격/구매링크) 카드로 함께 제안 (A6, 2026-07-29 결정) |
| 제휴 방식 | 네이버쇼핑 검색 API는 무료 공개 API라 수수료 없음 — 수익 모델이 아닌 "실제 구매 가능한 상품 노출"이 목적 |
| 자동 등록 | 🔸 미정 — 네이버쇼핑 API는 구매 확정 콜백을 제공하지 않아 `ClosetCommandPort`를 통한 `ClothingItem`(source=AUTO_PURCHASE) 자동 생성 방식은 별도 결정 필요 → [open-decisions.md](open-decisions.md) A6 |
